# 评分基础卡片架构设计

## 插件身份

- 插件 ID：`chips.basecard.score`
- 基础卡片类型：`base.score`
- 配置别名：`ScoreCard`
- 入口：`dist/index.mjs`

插件入口导出 `renderBasecardView`、`renderBasecardEditor` 和 `basecardDefinition`，与现有图片、音乐、网页、电子书基础卡片保持同一契约。

## 模块划分

- `src/schema/card-config.ts`：配置类型、默认值、归一化、校验和分数比例计算。
- `src/render/view.tsx`：查看态评分展示，保持无外层卡片壳视觉。
- `src/render/runtime.ts`：查看态 React 根节点挂载、主题 CSS 注入和 cleanup。
- `src/editor/panel.tsx`：样式选择、评分项点击、数字输入和配置提交。
- `src/editor/runtime.ts`：编辑面板容器尺寸接管、React 根节点挂载和样式恢复。
- `src/shared/i18n.ts`：本插件 `zh-CN` / `en-US` 文案加载。

## 运行时链路

查看态由 `renderBasecardView(ctx)` 挂载到宿主提供的 `ctx.container`。运行时先清空容器，再创建插件自己的 React 根节点，并注入 `ctx.themeCssText` 与插件局部样式。cleanup 会卸载 React 根并清空容器。

编辑态由 `renderBasecardEditor(ctx)` 直接挂载到编辑面板 DOM。编辑器不写文件，不访问资源桥，也不维护保存节流；每次有效变更都通过 `ctx.onChange(nextConfig)` 输出完整配置。

## 提交流程

编辑器内部使用 `configRef` 保存最新配置，避免连续点击样式和输入数字时因为 React 事件闭包拿到旧配置。提交流程为：

1. 将当前配置与局部 patch 合并；
2. 调用 `normalizeBasecardConfig(...)`；
3. 调用 `validateBasecardConfig(...)`；
4. 更新本地状态与错误状态；
5. 校验通过时调用 `onChange(nextConfig)`。

## 主题与多语言

- 所有可见 UI 文案来自 `i18n/zh-CN.json` 与 `i18n/en-US.json`。
- 查看态和编辑态样式均使用 `--chips-*` token，并保留 CSS fallback。
- 查看态不定义最外层描边、背景色或阴影，避免与编辑引擎装配层视觉重复。

## 资源边界

评分基础卡片没有内部资源字段，`basecardDefinition.collectResourcePaths(...)` 固定返回空数组。插件不调用 `importResource`、`resolveResourceUrl`、`deleteResource` 或 `openResource`。
