# 客户端架构与移植说明

## 1. 项目定位

薯片社区客户端（`com.chips.community-client`）是薯片生态的官方社区客户端应用插件，运行在薯片 Host surface 中。用户日常使用客户端访问薯片社区；网页版社区面向临时访客。

客户端与网页版使用同一套社区平台 HTTP API（`生态共用技术文档/协议与契约/09-社区平台API契约.md`），页面结构与视觉体验与网页版保持一致，并在此基础上提供网页版不具备的客户端能力：

- 直接调用社区卡片传输模块完成卡片上传与完整下载；
- 查看卡片时直接获取卡片资源，交给本地卡片查看器解析渲染，不依赖服务器渲染缓存。

## 3. 页面与路由映射

客户端使用 `HashRouter`（入口经 `file://` / `chips-render://` 加载，无法依赖服务端路由）。

| 路由 | 页面 | 与网页版差异 |
| --- | --- | --- |
| `/` | 欢迎页 / 登录态重定向 | 一致 |
| `/about` | 社区简介 | 一致 |
| `/login` `/register` | 登录 / 注册 | 一致，但登录态持久化走 Host credential（见 02） |
| `/@:username` | 个人主页 | 一致（批量删除确认改用 `platform.showConfirm`） |
| `/workspace` | 工作区 | 新增真实上传入口（网页版只有提示文案） |
| `/cards/:cardId` | 卡片详情 | 本地查看器打开 + 完整下载（见 03） |
| `/boxes/:boxId` | 箱子详情 | 展示箱子信息与引用卡片列表 |
| `/admin` | 管理员后台 | 在系统浏览器中打开后台页面 |
| `/settings` | 客户端设置 | 客户端新增（服务器地址 / 语言 / 账号） |
| `*` | 404 | 一致 |

## 4. 运行时接线

- `src/runtime/chips-client.ts`：`createClient()` 创建的 SDK client 单例，是页面组件访问系统能力的唯一入口（类型为完整 `Client`）。
- `AppProviders`：注入 `ChipsEnvironmentProvider`（主题、语言、surface、权限、诊断）与 `ChipsThemeProvider`（监听 `theme.changed` 事件）。
- `CommunityBootstrap`（在 `AppShell` 内）：启动时读取社区服务器地址并写入 API 客户端，绑定 refreshToken 读取器，之后才渲染业务界面。
- 命令链路：`useAppCommands` 注册 `openWorkspace / openSettings / refreshTheme`，`CommandRouterBridge` 将命令触发映射为路由跳转。

## 5. 与网页版的代码关系

- `src/community/` 下页面、组件、样式均为网页版 `Chips-CommunityPlatformServer/packages/web/src` 的正式移植，保持类名与文案键一致。
- 网页版的 `AppPreferencesContext`（t / formatDate / formatNumber）由 `src/community/contexts/PreferencesContext.tsx` 承接，文案解析接入薯片多语言系统（`useChipsI18nText` + localeBundles）。
- 网页版视觉 token（`--ccps-*`）原样移植到 `src/community/styles/runtime.css`，并新增客户端顶部导航样式（网页版 `SiteHeader` 未挂载，见工单126）。
- 网页版的服务器渲染缓存查看链路（open-view → viewUrl → 托管 iframe）在客户端不启用，由本地查看链路替代。

## 6. 边界与红线

- 不直接访问 Node.js / Electron 私有 API；所有系统能力经 SDK client。
- 不私自维护第二套上传下载协议；统一走 `community.card.transfer` 模块。
- 不在客户端内嵌管理员后台；后台一律在系统浏览器打开。
- 不依赖服务器渲染缓存作为查看主链路。
