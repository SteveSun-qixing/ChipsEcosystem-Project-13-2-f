# 卡片传输与本地查看链路

## 1. 总览

客户端所有卡片文件字节传输（上传 / 下载 / 本地查看）统一走社区卡片传输模块 `community.card.transfer`（由 `Chips-ModulePlugin/Chips-CommunityUploader-Plugin` 提供）。API 服务器只做控制面：鉴权、会话、签名、元数据、状态与任务调度，不接收 multipart `.card` 字节。

SDK 已提供类型化封装：`client.communityCardTransfer`（`chips-sdk` 的 `community-card-transfer` API）。

客户端侧封装：`src/community/lib/transfer.ts` 的 `createCommunityTransferService(client)`，负责：

- 组装模块调用输入（含当前登录会话 `baseUrl + accessToken`）；
- 调用 `client.communityCardTransfer.*`；
- 轮询模块 job（`client.module.job.get`，1.2s 间隔、30 分钟超时）；
- 归一化进度（`stage / percent / message`）与终态输出。

## 2. 本地查看（openRemote）

用户查看卡片时**不**访问服务器渲染缓存（viewUrl），而是：

1. `GET /api/v1/cards/:cardId/open-view` 读取卡片轻量信息（标题、作者、封面、状态）；
2. 调用 `communityCardTransfer.openRemote({ cardId, server })`；
3. 模块创建下载会话并读取下载计划，只下载网络资源卡片（networkCard）到用户设备临时目录；
4. 模块通过 Host `surface.open` 启动本地卡片查看器 `com.chips.card-viewer`，传入 `cardSource: { kind: "local-file", documentKind: "card", filePath }` 与 `communityServer` 上下文；
5. 本地卡片查看器解析网络资源卡片，资源按 CDN URL 在线加载渲染。

该链路只消费网络资源卡片本身，不等同于完整回下载。

### 客户端界面入口

卡片详情页（`src/community/pages/CardDetailPage.tsx`）：

- 「在本地查看器中打开」→ `transferService.openInLocalViewer(cardId)`；
- 打开过程展示进度（`card.viewOpening` + 模块阶段），成功展示 `card.viewOpened`，失败展示错误；
- 未登录时禁用并提示 `client.transfer.notLoggedIn`。

## 3. 完整下载（download）

卡片详情页「下载完整卡片」：

1. `client.platform.saveFile` 选择保存路径（默认文件名 = 卡片标题 + `.card`）；
2. `transferService.downloadCard(cardId, outputPath)` → 模块创建下载会话、读取计划、下载网络资源卡片与所有资源对象、把 URL 还原为原始相对路径并按 ZIP Store 重打包完整离线卡片；
3. 成功提示保存路径，失败展示错误。

## 4. 上传（upload）

工作区页（`src/community/pages/WorkspacePage.tsx`）：

1. `client.platform.openFile` 选择 `.card` / `.box` 文件（过滤器 `*.card; *.box`，文案键 `workspace.uploadFilter`）；
2. `transferService.uploadCard(filePath)`：
   - 模块读取完整离线卡片、枚举内部资源；
   - 创建上传会话（`publish.roomId = null`，`idempotencyKey` 自动生成）；
   - 分批申请对象存储 PUT 地址并直传资源；
   - 把配置中相对路径改写为对象存储/CDN URL 生成网络资源卡片；
   - 直传网络资源卡片并提交资源清单与可逆恢复清单；
3. 成功后展示 `communityUrl`，可点击「打开卡片页面」→ `client.platform.openExternal` 在系统浏览器打开；
4. 失败展示错误，未登录提示先登录。

`handleUpload` 按扩展名分流：`.box` 调用 `transferService.uploadBox`，其余按卡片处理。

## 4.1 箱子上传（uploadBox）

工作区页选择 `.box` 文件后调用 `transferService.uploadBox(filePath)`：

1. 模块侧流程：`box.inspect` → `box.unpack` → 收集散落卡片（`file://` 引用走 `uploadCommunityCard` 上传，内嵌相对路径与 http(s)/webdav 网络引用跳过）→ 回写工作副本 structure.yaml（散落卡片 URL 改写为社区公开 URL）→ 创建 box 上传会话 → 预签名直传对象存储 → complete 提交 metadata/structure/content；
2. 返回归一化结果 `BoxUploadResult`：`boxId / communityUrl / uploadedCards[] / skippedCards[] / warnings?`；
3. 界面展示：结果行显示「上传散落卡片数 / 跳过数」（`workspace.boxUploadResultSummary`），warnings 以提示列表展示（`workspace.boxUploadWarningsLabel`）；成功横幅文案区分卡片 / 箱子 / 混合（`workspace.uploadComplete` / `workspace.boxUploadComplete` / `workspace.uploadCompleteMixed`），打开按钮文案 `workspace.uploadCompleteOpen` / `workspace.boxUploadCompleteOpen`。

## 5. 任务进度与错误语义

- 模块任务状态：`running / completed / failed / cancelled`；
- 进度字段：`stage / percent / message`（上传：inspect → unpack → scan → session → upload-resources → rewrite → pack → submit → completed；箱子上传：inspect → unpack → collect-loose-cards → upload-loose-cards → rewrite → session → upload-box → submit → completed；下载：session → download-card → unpack → restore → pack → completed；打开：session → download-card → open → completed）；
- 失败错误带错误码（如 `COMMUNITY_TRANSFER_UPLOAD_FAILED`、`COMMUNITY_TRANSFER_BOX_UPLOAD_FAILED`），客户端原样透传到界面；
- 缺少登录会话时抛出 `COMMUNITY_TRANSFER_SESSION_MISSING`，不发起模块调用。

## 6. 前置条件

- Host 中必须安装并启用 `chips.module.chips.community-uploader`（`.chips-host-dev` 开发工作区已启用）；
- 插件 manifest 需声明 `module.invoke` 权限（客户端已声明）；
- 模块 `openRemote` 依赖 `com.chips.card-viewer` 已安装（客户端开发工作区已具备）。
