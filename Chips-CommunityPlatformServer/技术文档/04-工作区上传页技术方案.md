# 工作区上传页技术方案

## 1. 页面目标

工作区页只围绕上传任务建模，不再承担工作台聚合职责。

## 2. 输入方式

必须同时支持两种输入路径：

1. 拖拽文件进入页面；
2. 点击拖拽区调起文件选择器。

## 3. 文件识别

前端根据文件扩展名直接判定类型：

- `.card` -> 卡片上传
- `.box` -> 箱子上传

不再保留旧版手动模式切换。

## 4. 上传默认参数

为保持页面极简，前端统一采用：

- `roomId: undefined`
- `visibility: 'public'`

也就是默认上传到用户根目录并公开发布。

## 5. 队列模型

推荐统一使用：

```ts
type UploadQueueItem = {
  localId: string;
  file: File;
  type: 'card' | 'box';
  status: 'queued' | 'uploading' | 'processing' | 'success' | 'error';
  progress: number;
  remoteId?: string;
  resultHref?: string;
  errorMessage?: string;
};
```

## 6. 卡片上传流程

1. 调用 `POST /api/v1/upload/card`；
2. 利用现有上传回调显示百分比；
3. 服务端校验并保存处理后的 `.card` 到 `chips-card-files`；
4. 服务端写入卡片元数据并创建完整查看缓存与封面缓存渲染任务；
5. `POST /api/v1/upload/card` 返回 `202` 时表示源 `.card` 已保存，查看缓存异步生成；
6. 轮询 `GET /api/v1/cards/:cardId/render-status` 获取查看缓存状态；
7. `viewState = cache_ready` 时进入成功态并打开 `/api/v1/cards/:cardId/view`；
8. `viewState = rendering` 时显示准备中；
9. `viewState = render_error` 时进入失败态。

说明：网页兼容上传接口只接收已经处理好的 `.card`。官方本地上传器应优先使用上传会话接口，在用户设备上完成资源外置、链接替换、富文本 `content_source=file` 内联处理和重新打包，再提交处理后的 `.card`。

## 7. 箱子上传流程

1. 调用 `POST /api/v1/upload/box`；
2. 上传成功即进入成功态；
3. 为结果卡片写入 `resultHref`。

## 8. 并发策略

- 前端工作区队列采用有限并发调度，当前并发上限为 `3`；
- 每个任务从 `queued` 进入 `uploading` 后独立完成上传、卡片状态轮询或箱子成功收口；
- 卡片任务进入服务端 `processing` 后不会继续阻塞其他 queued 文件启动上传；
- 服务端上传接收阶段采用流式写入临时文件，不把完整 `.card` / `.box` 先聚合成内存 Buffer；
- 卡片完整查看缓存目录和封面缓存目录上传对象存储时采用有限并发；
- 对象存储并发由服务端环境变量 `CARD_RENDER_CACHE_UPLOAD_CONCURRENCY` 控制，默认值为 `8`。

## 9. 页面反馈

### 9.1 空闲态

- 显示大拖拽区；
- 给出支持格式与拖拽提示。

### 9.2 有队列时

- 拖拽区仍保留；
- 下方显示最近上传队列；
- 成功项允许一键返回个人页或打开内容。
