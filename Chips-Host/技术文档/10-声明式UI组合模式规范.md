# 声明式 UI 组合模式规范（L8）

> 文档状态：执行稿  
> 适用范围：`Chips-Host/src/renderer/declarative-ui/*` 与上层页面编排层

---

## 1. 目标

- 为 L8 声明式 UI 提供统一的组合模式约束。
- 采用 Vercel 组合模式，优先 Compound Components，避免 boolean 模式扩张。
- 固化事件绑定与副作用分级模型，禁止渲染阶段直接触发 `runtime-effect`。

---

## 2. 核心语义原语

L8 对外只暴露语义原语，不暴露视觉实现细节：

- `View`
- `Stack`
- `Grid`
- `Form`
- `List`
- `Section`
- `ScrollView`
- `Text`
- `Image`
- `Media`
- `Table`
- `Navigation`
- `Toolbar`
- `Command`
- `Slot`

所有原语统一输出 `UINode`：

```ts
interface UINode {
  id: string;
  type:
    | 'View'
    | 'Stack'
    | 'Grid'
    | 'Form'
    | 'List'
    | 'Section'
    | 'ScrollView'
    | 'Text'
    | 'Image'
    | 'Media'
    | 'Table'
    | 'Navigation'
    | 'Toolbar'
    | 'Command'
    | 'Slot'
    | string;
  props?: Record<string, unknown>;
  state?: Record<string, unknown>;
  bindings?: Record<string, string>;
  events?: Record<string, string>;
  themeScope?: string;
  modifiers?: NodeModifiers;
  children?: UINode[];
}
```

Modifier 只承载语义：

- `themeScope/i18nKey`
- `layout/accessibility/focusScope`
- `shortcut/permission`
- `presentation/motion/testId`

`themeScope` 与 `modifiers.themeScope` 同时存在时必须一致。`props` 禁止写入视觉硬编码字段，布局、焦点、权限、快捷键、动效等横切语义必须优先落在 modifier。

## 3. Compound Components 规范

### 3.1 允许模式

- 组件以“根节点 + 显式 slot 子节点”组合。
- slot 在定义时声明 `required/type/multiple`。
- slot 可附带 `part/role/description`，供组件库 contract、主题 `data-part` 与 a11y 规则对齐。
- Provider（页面域）是唯一状态实现知情者，L8 只消费已注入状态。

### 3.2 禁止模式

- 禁止通过多个 boolean 属性驱动多模式渲染（例如 `isCompact/isInline/showFooter` 组合）。
- 禁止在 slot 未声明时注入临时子节点。
- 禁止在 L8 层写主题视觉值。
- 禁止通过 `props` 写入 `style/color/backgroundColor/borderRadius/shadow/fontSize/width/height/margin/padding` 等视觉或尺寸硬编码。

### 3.3 工具约束

- 使用 `createCompoundComponent` 创建复合组件契约。
- 使用 `StandardCompoundSlotSchemas` 复用 `Dialog/Tabs/Menu/Form/DataGrid` 标准复杂组件 slot schema。
- 使用 `CompoundComponent.validate()` 在 compose 前获取结构化诊断；`compose()` 遇到 `severity=error` 的诊断时抛出对应 `DECLARATIVE_UI_*` 错误。
- 默认启用 `guardAgainstBooleanModeProps`，阻断 boolean 模式扩张。
- 业务变体通过显式组件/slot 组合表达，而不是 boolean 开关。

### 3.4 结构化诊断

L8 组合诊断结构：

```ts
interface DeclarativeUIDiagnostic {
  nodeId: string;
  type: UINode['type'];
  path: string;
  stage: 'slot-validate' | 'event-bind' | 'effect-dispatch' | 'node-normalize';
  severity: 'error' | 'warning' | 'info';
  code: string;
  message: string;
  suggestion?: string;
  details?: unknown;
}
```

诊断必须包含可定位的 `path` 和可执行的 `suggestion`，供 L9、SDK CLI 和脚手架质量门禁消费。

## 4. 事件绑定与副作用分级

### 4.1 事件绑定

- `events` 仅声明语义事件 -> 处理器 ID 映射（如 `onSubmit -> submit.handler`）。
- 处理器通过 `EventBindingRegistry.registerHandler` 注册。
- 事件分发统一走 `EventBindingRegistry.dispatch`。
- 事件预检使用 `validateNodeEventBindings` 输出结构化诊断，不执行 handler。

### 4.2 副作用分级

- `ui-effect`：滚动、聚焦、过渡。
- `runtime-effect`：调用 Runtime Client 或 Host 能力。
- `telemetry-effect`：埋点与日志上报。

### 4.3 渲染阶段约束

- `EffectDispatcher.dispatch` 在 `phase=render` 且 effect 为 `runtime-effect` 时直接拒绝：
  - 错误码：`DECLARATIVE_UI_RUNTIME_EFFECT_FORBIDDEN_IN_RENDER`
- 如需延迟执行，必须显式调用 `schedule()` 并在 `commit` 阶段 `flushScheduledRuntimeEffects()`。

## 5. 质量门禁

- 单测覆盖：语义原语、节点模型、组合约束、事件绑定、副作用分发。
- 关键约束测试：
  - 扩展原语和 modifier 校验
  - 视觉硬编码 props 拦截
  - events/bindings 非字符串拦截
  - boolean 模式 props 拦截
  - required slot 校验
  - `runtime-effect` 渲染阶段阻断
  - `ui-effect/telemetry-effect` 正常分发
