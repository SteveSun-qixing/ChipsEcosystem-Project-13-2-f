# 社区卡片传输模块技术方案

> 模块 ID：`chips.module.chips.community-uploader`
> 能力：`community.card.transfer`
> 更新时间：2026-08-05
> 本模块只在薯片客户端/Host 中运行；Web 浏览器运行时不加载。

## 1. 职责边界

- 在用户设备上处理 `.card` 上传、网络资源卡片生成、远程打开和完整卡片下载恢复；
- 只通过 Host `window.chips.*` / `chips-sdk` 正式链路访问系统能力；
- 通过社区 `card-transfer` 控制面 API 与服务器交互，文件字节直传对象存储/CDN；
- 统一处理对象存储 URL 改写与下载恢复，禁止调用方插件自行替换 YAML 或 HTML。
- 富文本 file-backed 内容内联：上传时把 `content_source: file` + `content_file` 内联为 `content_source: inline` + `content_text`，下载恢复时按恢复清单还原为 file-backed 并写回 markdown 资源。

## 2. 能力与契约

- `upload`：上传完整离线卡片，生成网络资源卡片并提交资源清单和恢复清单；
- `download`：按下载计划恢复完整离线卡片；
- `openRemote`：下载社区卡片的网络资源卡片到本地临时目录，通过 `surface.open` 启动本地卡片查看器（`com.chips.card-viewer`）解析渲染，资源按 CDN URL 在线加载；
- `getStatus` / `cancel`：由 Host `module.job.*` 任务链路承载。

输入输出 schema：

- `contracts/upload.input.schema.json`
- `contracts/upload.output.schema.json`
- `contracts/download.input.schema.json`
- `contracts/download.output.schema.json`
- `contracts/openRemote.input.schema.json`
- `contracts/openRemote.output.schema.json`

## 3. 运行边界

| 目标 | 支持 | 说明 |
| --- | --- | --- |
| Desktop Host | 是 | 上传、下载、远程打开 |
| Mobile Host/PAL | 是 | 按同一能力契约支持 |
| Web 浏览器 | 否 | 浏览器只负责社区网页查看，不加载本模块 |
| Headless | 是 | 用于自动化与测试链路 |

## 4. 错误与任务事件

统一使用 `createCommunityUploaderError(code, message, details, retryable)`：

- `COMMUNITY_TRANSFER_INPUT_INVALID`
- `COMMUNITY_TRANSFER_CANCELLED`
- `COMMUNITY_TRANSFER_NETWORK_FAILED`
- `COMMUNITY_TRANSFER_AUTH_EXPIRED`
- `COMMUNITY_TRANSFER_HTTP_ERROR`
- `COMMUNITY_TRANSFER_RESPONSE_INVALID`
- `COMMUNITY_TRANSFER_OBJECT_UPLOAD_FAILED`
- `COMMUNITY_TRANSFER_OBJECT_DOWNLOAD_FAILED`
- `COMMUNITY_TRANSFER_FILE_LIST_FAILED`
- `COMMUNITY_TRANSFER_CARD_NOT_STORE_ZIP`
- `COMMUNITY_TRANSFER_UPLOAD_FAILED`
- `COMMUNITY_TRANSFER_DOWNLOAD_FAILED`

进度阶段：

- 上传：`inspect -> unpack -> scan -> session -> upload-resources -> rewrite -> pack -> submit -> completed`
- 下载：`session -> download-card -> unpack -> restore -> pack -> completed`

重试与取消：

- 控制面请求和对象存储 PUT/GET 使用指数退避重试（最多 3 次）；
- 5xx / 408 / 429 视为瞬时失败自动重试；
- 401 / 403 立即抛出 `COMMUNITY_TRANSFER_AUTH_EXPIRED`，由调用方刷新签名后重新发起；
- 每次重试前检查任务信号，取消时抛出 `COMMUNITY_TRANSFER_CANCELLED`。

## 5. 第三方依赖评审

| 依赖 | 用途 | 许可证 | 维护状态 | 包体 | 安全风险 | 跨端 | 替代方案 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `yaml@^2.8.2` | 解析与写出 content/*.yaml 和封面配置，完成 URL 改写与恢复 | MIT | 活跃 | 极小（仅此模块内） | 无已知高危 | 纯 JS，Desktop/Mobile/Headless 均可 | 使用 JSON 配置文件会破坏现有卡片格式；不使用手写 YAML 解析器 |

说明：

- 该模块运行期唯一第三方依赖是 `yaml`，用于读写卡片配置 YAML；
- 已在卡片格式规范与社区 API 契约中收口资源改写语义，`yaml` 只做格式解析，不承担社区文件链路逻辑；
- 对象存储签名、ZIP Store 读写、任务调度均走 Host 正式能力，不新增运行时依赖；
- 开发依赖（vitest / typescript / eslint / esbuild / chips-sdk）只用于构建与测试辅助，不打进产物。

## 7. 权限说明（2026-08-05 补充）

`openRemote` 需要在用户设备上启动本地卡片查看器（`com.chips.card-viewer`），因此模块 manifest 声明以下额外权限：

- `window.control`：`surface.open` 动作的基础权限（创建 surface）；
- `plugin.manage`：`surface.open` 对 `type: plugin` 目标打开时的额外要求（Host 校验 `ensureCallerPermission(routeContext, 'plugin.manage', 'surface.open')`）。

缺少任一权限时，`openRemote` 会在下载 networkCard 成功后于 `surface.open` 阶段抛出 `PERMISSION_DENIED`。

## 8. 安装说明

- `openRemote` / `upload` / `download` 依赖模块被安装并启用；
- 客户端所在开发工作区（`.chips-host-dev`）必须通过 `chipsdev plugin install <cpk>` 安装本模块并 `chipsdev plugin enable`；
- 重新构建模块后需要 **先 uninstall 再 install**（`chipsdev plugin install` 不会替换已存在副本的 manifest 权限）；
- 若模块未安装，客户端点击社区卡片会回退到打开网页（旧行为），上传也会失败。
