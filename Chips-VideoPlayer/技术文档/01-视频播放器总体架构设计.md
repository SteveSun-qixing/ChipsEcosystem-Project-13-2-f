# 视频播放器总体架构设计

## 1. 项目角色

`Chips-VideoPlayer` 是薯片生态中的应用插件视频查看器。它不承载视频解码内核或转码服务，只负责：

1. 恢复要播放的视频目标；
2. 为当前视频目标构建正式播放会话；
3. 承载控制条、播放区域和状态反馈；
4. 调用 Host 正式文件与平台能力。

## 2. 分层结构

当前实现分为六层：

### 2.1 App Entry

- 文件：`src/App.tsx`
- 职责：
  - 仅将 `AppRoot` 作为正式 `App` 导出；
  - 不承载 Host 能力初始化或业务状态。

### 2.2 App Runtime / Scene

- 文件：
  - `src/app/AppRoot.tsx`
  - `src/app/AppProviders.tsx`
  - `src/app/AppRuntimeProvider.tsx`
  - `src/app/AppShell.tsx`
  - `src/app/scene-registry.ts`
- 职责：
  - 初始化 `chips-sdk` 客户端；
  - 通过 `ChipsEnvironmentProvider` 读取主题、语言、surface、权限与诊断；
  - 从 Host `surfaceContext / launchParams` 恢复启动上下文；
  - 归一视频源；
  - 协调打开、保存和拖放行为。
  - 注册并消费 Host command registry。

### 2.3 Commands

- 文件：
  - `src/commands/video-player-commands.ts`
  - `src/commands/useVideoPlayerCommands.ts`
- 职责：
  - 维护稳定 `commandId / handlerId`；
  - 只使用 `titleKey / descriptionKey / ariaLabelKey`；
  - 派生命令启用、选中和禁用原因状态；
  - 将 `command.invoked` 事件分发给 App Runtime 中的同一批播放动作。

### 2.4 Runtime Hooks

- 文件：
  - `src/hooks/useVideoPlayerController.ts`
- 职责：
  - 管理 `<video>` 元素运行时状态；
  - 收口播放、暂停、时间轴、音量、全屏、画中画和热键行为。

### 2.5 View Stage

- 文件：`src/components/VideoPlayerStage.tsx`
- 职责：
  - 只负责展示与事件绑定；
  - 不直接知道 Host 路由细节；
  - 使用 Controller 暴露的状态组装界面；
  - 按按钮、空态和更多面板触发正式 command id。
  - 运行时按钮图标消费 `ChipsIcon + IconDescriptor`，图标字重、大小和颜色由主题 token 控制。

### 2.6 Pure Utils

- 文件：
  - `src/utils/video-player.ts`
  - `src/utils/launch-resource.ts`
- 职责：
  - 保持纯函数；
  - 处理文件名、格式支持、时间格式化、启动参数归一与媒体错误映射。

## 3. 依赖边界

项目只依赖：

1. React
2. `@chips/component-library` 的 Environment、Theme 与 Command Provider
3. `chips-sdk`
4. 原生 HTML5 `<video>`

项目不依赖：

1. Electron 私有对象
2. Host 内部源码模块
3. 第三方播放器运行时 npm 包

## 4. DPlayer 参考策略

本项目参考 DPlayer 的部分思路包括：

1. 控制条分组；
2. 热键语义；
3. 播放控制器与界面模板解耦。

正式实现不直接导入 DPlayer 运行时，而是把这些经验重写为：

1. `useVideoPlayerController(...)`
2. `VideoPlayerStage`
3. 基于生态主题 token 派生的播放器控制层 CSS

这样可以避免把第三方运行时外溢为生态正式接口。
