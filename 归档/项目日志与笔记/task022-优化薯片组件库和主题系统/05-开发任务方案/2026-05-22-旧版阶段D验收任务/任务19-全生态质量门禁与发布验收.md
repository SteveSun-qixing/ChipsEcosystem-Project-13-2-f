# 任务19：全生态质量门禁与发布验收

## 1. 任务目标

建立前端框架 vNext 的全生态质量门禁，确保 Host、SDK、组件库、脚手架、主题包、设置面板和示例应用整体可用。

这是进入第一版发布前的总验收任务。

## 2. 当前基础

当前已有脚本：

- 根目录：`npm run verify:workspace`
- Host：`npm run build`、`npm test`、`npm run test:contract`、`npm run test:perf:l9`
- SDK：`npm test`
- 组件库：`npm run verify`、`npm run quality:gate`
- 脚手架：`build/test/test:templates/test:e2e`
- 设置面板：`npm run verify`
- 主题包：各主题 `npm test`

## 3. 涉及项目

- 全生态工作区。

## 4. 开发内容

1. 建立总质量门禁脚本或手册。
   - workspace 校验。
   - Host。
   - SDK。
   - ComponentLibrary。
   - Scaffold。
   - ThemePack。
   - EcoSettingsPanel。
   - 示例应用。

2. 定义门禁类别。
   - build。
   - typecheck。
   - unit test。
   - contract test。
   - a11y test。
   - performance test。
   - scaffold generated e2e。
   - theme contract。
   - manifest validate。
   - i18n validate。

3. 定义发布阻断项。
   - Host/SDK 公共契约不一致。
   - 组件 contract 缺失。
   - 默认主题或暗色主题 token 缺失。
   - 脚手架生成工程不可运行。
   - 应用直接调用 Electron/Node。
   - 文案绕过 i18n。
   - 视觉绕过主题 token。
   - L9 性能阈值失败。

4. 生成质量报告。
   - 每个项目状态。
   - 每类测试状态。
   - 失败项。
   - 责任任务。
   - 修复建议。

5. 接入设置面板或 CLI。
   - CLI 可输出 JSON 报告。
   - 设置面板可展示关键质量状态。

## 5. 建议文件范围

- 根目录 `scripts/*`
- 根目录 `package.json`
- `Chips-SDK/cli/index.js`
- `Chips-ComponentLibrary/scripts/*`
- `Chips-EcoSettingsPanel/src/*`
- `项目日志与笔记/task022-优化薯片组件库和主题系统/*`

## 6. 验收标准

- 有一套明确的全生态验收流程。
- 所有关键项目脚本通过。
- 质量报告可被机器读取，也可被人阅读。
- 发布阻断项定义清楚。
- 失败时能定位到具体项目和任务。

## 7. 验证命令

建议最终验收至少运行：

```bash
npm run verify:workspace
cd Chips-Host && npm run build && npm test && npm run test:contract && npm run test:perf:l9
cd ../Chips-SDK && npm test

cd ../Chips-Scaffold/chips-scaffold-app && npm run build && npm test && npm run test:templates && npm run test:e2e
cd ../../ThemePack/Chips-default && npm test
cd ../Chips-theme-default-dark && npm test
cd ../../Chips-EcoSettingsPanel && npm run verify
```
