# 应用插件开发

## 文档定位

本文档说明 `type: app` 插件的正式开发口径。

当前关键变化：

- 应用插件已升级为跨平台界面插件
- 正式容器语义从 `window` 升级为 `surface`
- Manifest 必须声明 `runtime.targets` 与 `ui.surface`

## 1. 应用插件的正式定义

应用插件不是“只能在桌面独立窗口里运行的 HTML 页面”，而是：

- 由 Host 托管
- 通过 `surface` 语义启动
- 可按宿主映射到不同界面容器的跨平台界面插件

当前映射：

- Desktop：`window`
- Web：预留 `route / tab / modal`
- Mobile：预留 `fullscreen / sheet`

## 2. 基本结构

应用插件工程至少包括：

- 工程根 `manifest.yaml`
- 前端入口文件
- 构建产物目录 `dist/`
- 静态资源

正式约束：

- `entry` 应指向构建产物，例如 `dist/index.html`
- 入口页必须声明正式 `Content-Security-Policy`
- 静态资源路径必须支持 Host 以本地入口方式加载

## 3. 必填 Manifest 重点字段

应用插件必须重点声明：

```yaml
type: app
entry: dist/index.html
runtime:
  targets:
    desktop:
      supported: true
    web:
      supported: false
    mobile:
      supported: false
    headless:
      supported: false
ui:
  surface:
    defaultKind: window
    preferredKinds:
      desktop: window
      web: route
      mobile: fullscreen
      headless: window
```

可选但常用字段：

- `ui.window.chrome`
- `ui.launcher`
- `capabilityFallbacks`
- `capabilities`

## 4. 启动链路

当前应用插件正式启动方式有两条：

1. `client.surface.open({ target: { type: "plugin", pluginId } })`
2. `client.plugin.launch(pluginId, launchParams?)`

推荐顺序：

- 新的跨平台调用优先使用 `surface.open(target=plugin)`
- 已有桌面兼容代码可以继续使用 `plugin.launch`

### 启动上下文

应用插件如果要知道“为什么被打开”，必须读取 launch context：

```ts
const launchContext = client.platform.getLaunchContext();
```

或：

```ts
const launchContext = window.chips.platform.getLaunchContext();
```

返回：

```ts
{
  pluginId?: string;
  sessionId?: string;
  sceneId?: string;
  surfaceId?: string;
  kind?: "window" | "tab" | "route" | "modal" | "sheet" | "fullscreen";
  presentation?: {
    title?: string;
    width?: number;
    height?: number;
    resizable?: boolean;
    alwaysOnTop?: boolean;
  };
  surfaceContext?: {
    surfaceId?: string;
    sceneId: string;
    pluginId?: string;
    sessionId?: string;
    kind: "window" | "tab" | "route" | "modal" | "sheet" | "fullscreen";
    presentation: {
      title?: string;
      width?: number;
      height?: number;
      resizable?: boolean;
      alwaysOnTop?: boolean;
    };
    launchParams?: Record<string, unknown>;
    documentContext?: {
      documentId: string;
      title?: string;
      url?: string;
    };
    commandContext?: {
      commandId: string;
      source?: string;
      payload?: Record<string, unknown>;
    };
  };
  launchParams: Record<string, unknown>;
}
```

`surfaceContext` 是 App / Scene 运行心智的正式上下文：

- `sceneId` 标识一次由 Host 管理生命周期的界面场景。
- `surfaceId` 标识当前宿主容器。Desktop 当前映射为窗口，但应用代码不得依赖 `BrowserWindow`。
- `kind` 表示公共 surface 语义，实际宿主形态由 PAL 映射。
- `presentation` 表示 Host 解析后的标题、尺寸、可调整性和壳层呈现基线。
- `documentContext` 与 `commandContext` 供后续 Document Scene 和 Commands 链路复用。

常见触发来源：

- `app-shortcut`
- `file-association`
- `chipsdev.run`
- `resource.open`

## 5. Commands 注册与调度

应用插件的菜单、工具栏、快捷键、命令面板和上下文菜单动作必须通过 `chips-sdk` 的 `client.command.*` 或 `window.chips.command.*` 注册到 Host command registry。

最小注册示例：

```ts
const client = createClient();

await client.command.register({
  commandId: "chips.example.open-settings",
  titleKey: "app.commands.openSettings.title",
  descriptionKey: "app.commands.openSettings.description",
  ariaLabelKey: "app.commands.openSettings.ariaLabel",
  icon: { name: "settings", style: "rounded" },
  scope: { kind: "app", appId: "chips.example" },
  permission: ["config.read"],
  handlerId: "open-settings",
  menuPlacement: [{ menuId: "app", groupId: "settings", order: 10 }],
  toolbarPlacement: [{ toolbarId: "main", groupId: "primary", order: 10 }],
  paletteKeywords: ["settings", "preferences"]
});
```

Command schema 约束：

- 文案只能写 `titleKey / descriptionKey / ariaLabelKey`，不得写 `title / description / ariaLabel` 原始文本。
- `icon` 必须是运行时 `IconDescriptor`，由 `ChipsIcon` 渲染，不等同于 `manifest.ui.launcher.icon`。
- `handlerId` 是插件侧处理器标识，Host 不接收函数。
- `permission` 是执行该命令所需的业务权限，必须已在插件 manifest permissions 中声明。
- `scope.kind` 支持 `app / scene / surface / document / global`。普通应用插件默认使用 `app`，注册 `global` 需要 `command.manage`。
- `enabledWhen / visibleWhen / checkedWhen` 仅支持 boolean 或结构化 condition；后续 State / Environment / Binding 接入时继续复用该结构。

调用和事件：

- 菜单、工具栏、快捷键、命令面板统一调用 `command.invoke`。
- Host 校验通过后发出 `command.invoked`，载荷包含 `invocationId / commandId / handlerId / ownerPluginId / ownerSessionId / source / sceneId / surfaceId / documentId / payload`。
- 插件侧 SDK 根据 `handlerId` 和 owner 上下文执行本地 handler。
- 插件 surface 关闭、插件禁用或卸载时，Host 会清理该 session/plugin 注册的 commands。

官方应用脚手架基线：

- `chips-scaffold-app` 生成的标准应用默认声明 `i18n.read / i18n.write / command.read / command.write / command.invoke`。
- 模板根组件通过 `ChipsEnvironmentProvider` 注入 SDK `createClient()` 生成的 client，业务组件通过 `useChipsTheme/useChipsI18n/useChipsSurface/useChipsPermission/useChipsDiagnostics` 读取 Host 环境。
- 模板本地语言包通过 `localeBundles` 和 `supportedLocales` 对外提供渲染期输入，根组件、命令消费组件和示例组件统一使用 `useChipsI18nText()` 解析同步文案。
- 模板语言切换入口通过 `useChipsI18n().setLocale()` 调用 SDK/Host 的 `i18n.setCurrent({ locale })`，因此必须配套 `i18n.write` 权限。
- 生成工程使用 `src/commands/` 集中维护 command metadata、稳定 command id、`handlerId` 和插件侧事件处理。
- 命令 hook 通过 `useChipsClient()` 取得同一个 SDK client，再由 `ChipsCommandProvider` 和 `createCommandAdapter(client)` 把 SDK `client.command.*` 注入组件库。
- `ChipsMenuBar / ChipsToolbar / ChipsCommandPalette` 从 `client.command.list()` 读取命令，触发时统一走 `client.command.invoke()`。
- 模板测试必须证明根组件使用 React Environment 正式入口，命令定义不包含原始文案字段，不生成私有 `useChipsBridge` 入口，不绕过 SDK 直连 `command.*` Bridge action，不直接访问 Electron / Node 系统能力。

## 6. 系统入口与快捷方式

应用插件可以通过 `ui.launcher` 声明系统入口元数据。

当前正式链路：

1. 治理应用调用 `plugin.createShortcut`
2. Host 读取 `ui.launcher.displayName` 与 `ui.launcher.icon`
3. Host 通过 PAL / Shell 创建平台入口
4. 用户触发入口后，Host 统一走应用插件正式启动链路

约束：

- 应用插件不得自行创建 `.lnk`、`.app` 或其他系统快捷方式文件

## 7. 资源处理器

如果应用插件要承担资源查看 / 处理职责，应声明：

```yaml
capabilities:
  - resource-handler:view:image/*
  - file-handler:.png
  - file-handler:.jpg
```

上游应用应统一调用：

```ts
await client.resource.open({
  intent: "view",
  resource: {
    resourceId,
    mimeType,
    title,
    fileName,
  },
});
```

应用侧应从 launch context 中读取：

- `launchParams.resourceOpen`
- `launchParams.resourceOpen.payload`
- 必要时读取 `launchParams.targetPath`

说明：

- `launchParams.resourceOpen.payload` 用于接收上游通过正式 `resource.open` 透传的结构化上下文；
- 资源处理器应用可以据此恢复业务态，例如音乐播放器恢复音乐基础卡片里的封面、歌词和标题，但不得要求上游绕开 `resource.open` 私传插件私有参数。

## 8. 前端栈与 UI 规则

- 官方前端栈统一采用 React
- 界面文案必须走多语言系统
- 视觉样式必须走主题系统与 token
- 不得依赖 Electron 私有 API

## 9. 能力调用规则

应用插件访问 Host 能力必须使用：

- `chips-sdk`
- `window.chips.*`

不得：

- 直接访问 Node.js API
- 直接操作原生窗口对象
- 私下约定跨应用启动协议绕过 Host

## 9. 当前开发建议

1. 新工程直接使用官方 Scaffold 生成。
2. 发布前至少执行：
   - `chipsdev validate`
   - `chipsdev package`
3. 开发运行优先使用 `chipsdev run`，由完整 Host 链路托管应用插件。
