# 组件契约标准

## 1. 契约目标

统一生态组件结构和状态语义，保证主题包、测试工具、自动化扫描工具可稳定工作。

## 2. 强制字段

每个组件必须暴露：

- `data-scope`：组件名（小写短横线）
- `data-part`：部件名（root/label/icon/...）
- `data-state`：当前状态
- `aria-*`：无障碍语义属性

## 3. 状态模型

标准状态集合：

`idle | hover | focus | active | disabled | loading | error`

非标准状态需要额外在组件文档中声明并说明优先级。

## 4. 命名规则

- `data-scope`：`button`、`input`、`dialog`
- `data-part`：`root`、`trigger`、`content`、`label`、`icon`
- `data-state`：使用上述标准状态，不允许自造同义词

## 5. 兼容要求

- 契约字段变更视为破坏性变更
- 主题包不得依赖未公开 part 名称
- 控制型图标（展开/折叠/关闭/时间等）必须支持外部槽位覆盖，禁止写死用户可见字符

## 6. 示例

```html
<button
  data-scope="button"
  data-part="root"
  data-state="loading"
  aria-disabled="true"
>
  <span data-part="label">保存</span>
  <span data-part="spinner" aria-hidden="true"></span>
</button>
```

## 7. iframe 高级组件附加契约

只有 iframe 高级组件需要声明 iframe 附加契约。当前正式范围为 `CardCoverFrame`、`CompositeCardWindow`，必须额外声明：

- iframe 安全策略（sandbox/allow）
- frame 生命周期事件（`ready/error`）
- 降级状态（如 `degraded`）
- 跨 iframe 通信边界（仅受控事件通道）

普通无头组件和布局原语不声明 iframe 字段，契约校验不应要求它们提供 `iframe.requiredSandbox`。

## 8. 主题 Contract View 对接字段

组件 contract 进入主题系统时统一归一为 `ThemeContractComponentView`：

- `component`：组件技术名，使用小写短横线。
- `scope`：运行时 `data-scope`。
- `parts`：公开 `data-part` 集合。
- `states`：公开 `data-state` 集合。
- `requiredTokens`：主题包必须实现的 token key，缺失会产生 `THEME_REQUIRED_TOKEN_MISSING` 阻断诊断。
- `optionalTokens`：主题包可选实现的 token key，缺失只产生非阻断诊断。
- `a11yConstraints`：组件可访问性约束引用，由设置面板和测试工具展示。
- `motionConstraints`：组件动效约束引用，由主题包校验器和设置面板展示。
- `coverage`：required/optional token 覆盖率。
- `diagnostics`：该组件下的主题诊断列表。

历史 contract 文件中的 `tokens` 字段在公共 view 中视为 `requiredTokens`。新增 contract 应优先写 `requiredTokens / optionalTokens`，避免再扩散旧字段语义。

## 9. Primitive 作用域建议

生态推荐的 Primitive `data-scope`：

- 布局：`view`、`box`、`stack`、`inline`、`grid`、`section`、`scroll-view`、`spacer`、`divider`、`split-view`
- 文本：`text`、`label`、`helper-text`

这些 scope 作为主题包与自动化测试工具的基础约定，新增 scope 需同步文档。

已落地基础展示控件的正式组件导出：

- `ChipsText`：`data-scope="text"`，公开 part 为 `root`，状态为 `idle / disabled / error`，支持 `textKey / textParams / fallbackText` 同步 i18n 文案解析。
- `ChipsLabel`：`data-scope="label"`，公开 part 为 `root / required-indicator / status`，状态为 `idle / disabled / error`，必须通过 `htmlFor` 或可访问名称与控件语义建立关联。
- `ChipsIcon`：`data-scope="icon"`，公开 part 为 `root`，状态为 `idle`，以 `IconDescriptor` 作为唯一正式输入模型。

已落地任务015第二批基础控件的正式组件导出：

- `ChipsIconButton`：`data-scope="icon-button"`，公开 part 为 `root / icon / spinner / status`，状态为标准交互状态集合，必须通过 `aria-label` 或 `aria-labelledby` 提供可访问名称，主题热区 token 默认不低于 44cpx。
- `ChipsToggleButton`：`data-scope="toggle-button"`，公开 part 为 `root / icon / label / spinner / status`，状态为标准交互状态集合，切换态使用 `aria-pressed` 与 `data-pressed` 表达，不使用 `aria-checked`。
- `ChipsBadge`：`data-scope="badge"`，公开 part 为 `root / icon / label / status`，状态为 `idle / disabled / error`，可通过 `data-tone` 表达 `neutral / accent / success / warning / error` 语义。
- `ChipsTag`：`data-scope="tag"`，公开 part 为 `root / icon / label / close / status`，状态为标准交互状态集合；可关闭标签的 `close` part 必须是按钮并提供可访问名称。
- `ChipsAvatar`：`data-scope="avatar"`，公开 part 为 `root / image / fallback / status`，状态为 `idle / disabled / loading / error`，非装饰头像必须提供姓名或等价可访问标签。
- `ChipsSpinner`：`data-scope="spinner"`，公开 part 为 `root / track / indicator / status`，状态为 `idle / disabled / loading / error`，独立使用时必须 `role="status"` 且有可访问名称，嵌入装饰场景可 `aria-hidden="true"`。
- `ChipsProgress`：`data-scope="progress"`，公开 part 为 `root / track / range / label / value / status`，状态为 `idle / disabled / loading / error`，必须 `role="progressbar"`；确定进度输出 `aria-valuemin/max/now`，不确定进度不得输出 `aria-valuenow`。

已落地任务015第三批基础输入控件的正式组件导出：

- `ChipsTextField`：`data-scope="text-field"`，公开 part 为 `root / label / control / description / status`，状态为标准交互状态集合，必须通过 `label/labelKey/aria-label/aria-labelledby` 提供可访问名称。
- `ChipsTextArea`：`data-scope="text-area"`，公开 part 为 `root / label / control / description / status`，状态为标准交互状态集合，支持多行输入、描述、错误和 resize 模式。
- `ChipsSearchField`：`data-scope="search-field"`，公开 part 为 `root / label / search-icon / control / clear / description / status`，状态为标准交互状态集合，根节点使用 `role="search"`，`Enter` 触发搜索语义，清空按钮必须提供可访问名称。
- `ChipsSecureField`：`data-scope="secure-field"`，公开 part 为 `root / label / control / visibility-toggle / visibility-icon / description / status`，状态为标准交互状态集合，输入类型在 `password/text` 间切换，可见性按钮必须提供可访问名称并输出 `aria-pressed`。

已落地任务015第四批选择扩展控件的正式组件导出：

- `ChipsSegmentedControl`：`data-scope="segmented-control"`，公开 part 为 `root / item / indicator / label / status`，状态为标准交互状态集合，根节点必须提供可访问名称并使用 `role="radiogroup"`，每个分段项使用 `role="radio"` 与 `aria-checked` 表达单选状态。
- `ChipsComboBox`：`data-scope="combo-box"`，公开 part 为 `root / label / control / trigger / list / option / description / status`，状态为标准交互状态集合，输入控件使用 `role="combobox"`、`aria-autocomplete="list"`、`aria-expanded`、`aria-controls` 和 `aria-activedescendant` 关联弹层选项。

已落地任务015第五批数值控件的正式组件导出：

- `ChipsNumberInput`：`data-scope="number-input"`，公开 part 为 `root / label / control / decrement / increment / description / status`，状态为标准交互状态集合，输入控件使用 `role="spinbutton"`，输出 `aria-valuemin / aria-valuemax / aria-valuenow / aria-valuetext`，并通过 `data-at-min / data-at-max / data-empty / data-invalid` 表达数值边界和解析状态。
- `ChipsStepper`：`data-scope="stepper"`，公开 part 为 `root / label / decrement / value / increment / status`，状态为标准交互状态集合，根节点使用 `role="group"` 并提供可访问名称，递增和递减必须是真实按钮，边界禁用通过按钮 `disabled / aria-disabled` 与根节点 `data-at-min / data-at-max` 表达。
- `ChipsSlider`：`data-scope="slider"`，公开 part 为 `root / label / track / range / thumb / value / status`，状态为标准交互状态集合，`thumb` 使用 `role="slider"` 并提供可访问名称，输出 `aria-valuemin / aria-valuemax / aria-valuenow / aria-valuetext`，根节点通过 `data-orientation / data-at-min / data-at-max / data-value / data-ratio` 表达方向、边界和值状态。

已落地任务015第六批日期时间控件的正式组件导出：

- `ChipsDatePicker`：`data-scope="date-picker"`，公开 part 为 `root / label / control / input / trigger / calendar / header / previous / next / title / grid / week-header / cell / description / status`，状态为标准交互状态集合。输入控件使用 `role="combobox"`、`aria-expanded`、`aria-controls` 与 `aria-activedescendant` 关联日历网格；日历日期值使用 `YYYY-MM-DD` 字符串，不隐式转换时区或 `Date` 对象。
- `ChipsTimePicker`：`data-scope="time-picker"`，公开 part 为 `root / label / control / input / trigger / list / option / description / status`，状态为标准交互状态集合。输入控件使用 `role="combobox"`、`aria-expanded`、`aria-controls` 与 `aria-activedescendant` 关联时间选项列表；时间值使用 `HH:mm` 或显式秒级 `HH:mm:ss` 字符串，不隐式绑定日期或时区。

已落地布局原语的正式组件导出：

- `ChipsView`：页面、区域或主视图容器，默认 `role="region"`，标题可通过 `title/titleId/aria-label/aria-labelledby` 建立可访问名称。
- `ChipsBox`：通用结构容器，承载 padding、radius 与基础状态 token。
- `ChipsStack`：纵向或横向堆叠容器，支持 `direction/gap/align/justify/wrap`。
- `ChipsInline`：行内容器，默认可换行，支持 `gap/align/justify/wrap`。
- `ChipsGrid`：响应式网格容器，支持 `columns/minItemSize/gap`。
- `ChipsSection`：局部内容分区，默认 `role="region"`，支持标题、描述、正文、页脚与错误状态。
- `ChipsScrollView`：滚动区域，默认 `role="region"`，必须通过 `aria-label` 或 `aria-labelledby` 提供名称。
- `ChipsSpacer`：弹性占位，只作为装饰结构，必须 `aria-hidden="true"`。
- `ChipsDivider`：分割线，非装饰模式必须 `role="separator"` 并暴露方向。
- `ChipsSplitView`：主从或三栏视图容器，默认 `role="group"`，必须通过 `aria-label` 或 `aria-labelledby` 提供名称。

布局原语主题实现必须覆盖默认主题和暗色主题，且样式只能通过 `chips.comp.*` 与 `chips.layout.*` token、CSS 变量和公开 `data-scope/data-part/data-state` 挂点实现。网格最小条目、SplitView 栏宽、焦点环、分割线厚度等结构尺寸不得在主题 CSS 中写成私有固定值，应分别回到 `chips.layout.size.*`、`chips.layout.focus.*` 与 `chips.layout.divider.*`。

已落地命令消费组件的正式导出：

- `ChipsCommandProvider`：命令消费上下文，接收应用注入的 `CommandAdapter`、静态 command views、i18n adapter 与查询默认值。
- `ChipsToolbar`：`data-scope="toolbar"`，默认 `role="toolbar"`，按 `toolbarPlacement.toolbarId/groupId/order` 渲染 command。
- `ChipsToolbarItem`：`data-scope="toolbar"`、`data-part="item"`，渲染 command 图标、文案、快捷键提示并触发 command。
- `ChipsMenuBar`：`data-scope="menu-bar"`，默认 `role="menubar"`，按 `menuPlacement.menuId/groupId/order` 生成菜单结构。
- `ChipsContextMenu`：`data-scope="context-menu"`，提供右键/点击触发的无头上下文菜单结构。
- `ChipsShortcut`：`data-scope="shortcut"`，只负责快捷键视觉与可访问名称，不负责注册系统快捷键。
- `ChipsCommandPalette`：`data-scope="command-palette"`，可从 command views 派生面板条目，触发仍走 command invoke。

命令消费组件新增的公开部件：

- `toolbar`：`root / group / item / icon / label / shortcut / status`
- `menu-bar`：`root / menu / content / group / item / shortcut / status`
- `context-menu`：`root / trigger / content / group / item / shortcut / status`
- `shortcut`：`root / key / separator`

这些组件不得直接绑定业务函数；业务动作必须由 Host command registry 调度。图标必须通过 `ChipsIcon` 渲染，文案必须通过命令 i18n key 解析。

## 10. 图标组件正式契约

- 运行时图标统一由 `ChipsIcon` 承担；
- `ChipsIcon` 的正式输入是图标描述符对象，而不是字符串、emoji 或业务自定义枚举；
- `ChipsIcon` 根节点必须暴露：
  - `data-scope="icon"`
  - `data-part="root"`
  - `data-icon-style="outlined|rounded|sharp"`
- 装饰图标默认 `aria-hidden="true"`；
- 功能图标必须通过 `label` 或外部可访问名称提供语义；
- 任何组件默认图标、空态图标、工具栏图标都必须最终回到 `ChipsIcon`，不得在组件内部继续维护一套硬编码 SVG 主链路。
