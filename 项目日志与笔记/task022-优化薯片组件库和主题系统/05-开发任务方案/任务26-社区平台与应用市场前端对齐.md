# 任务26：社区平台与应用市场前端对齐

## 1. 任务目标

把 `Chips-CommunityPlatformServer` 中的 Web/Admin 前端与薯片前端框架的设计系统、组件库、主题 token、插件/主题/应用市场数据模型对齐。

社区平台不是 Host 插件运行时，但它是生态分发和应用市场的重要组成部分，视觉、组件、数据契约和治理口径不能与主生态割裂。

## 2. 当前基础

已核对：

- `Chips-CommunityPlatformServer/package.json`
- `Chips-CommunityPlatformServer/packages/server/package.json`
- `Chips-CommunityPlatformServer/packages/web/package.json`
- `Chips-CommunityPlatformServer/packages/admin/package.json`
- `生态设计原稿/20-社区服务器架构.md`
- `生态共用技术文档/协议与契约/09-社区平台API契约.md`

## 3. 涉及项目

- `Chips-CommunityPlatformServer`
- `Chips-ComponentLibrary`
- `ThemePack/*`
- `生态共用技术文档/协议与契约/09-社区平台API契约.md`

## 4. 开发内容

1. API 契约核对。
   - 插件发布。
   - 主题发布。
   - 版本信息。
   - 截图/预览资源。
   - 权限声明。
   - 审核状态。
   - 下载与安装元数据。

2. Web/Admin 前端 UI 对齐。
   - 使用薯片组件库或等价 contract。
   - 使用主题 token 或可映射 token。
   - 文案走平台 i18n。
   - 表单、表格、筛选、详情页、审核页统一组件模式。

3. 应用市场数据模型对齐。
   - app/card/layout/module/theme 五类插件。
   - `runtime.targets`。
   - `ui.surface`。
   - module capability。
   - theme contract。

4. 质量门禁。
   - build。
   - lint。
   - test。
   - API contract test。
   - 前端组件一致性检查。

5. 与 Host/SDK 协同。
   - 市场返回数据应能被 Host 安装链路消费。
   - 不让社区平台发明另一套插件 manifest。

## 5. 验收标准

- 社区平台插件/主题数据模型与生态 manifest 口径一致。
- Web/Admin 前端视觉与薯片设计系统一致。
- 社区平台不会输出 Host 无法安装的插件元数据。
- build/lint/test 通过。

## 6. 验证命令

```bash
cd Chips-CommunityPlatformServer
pnpm --filter @ccps/server test
pnpm --filter @ccps/server build
pnpm --filter @ccps/web build
pnpm --filter @ccps/admin build
pnpm lint
```

如果本地未安装 pnpm 或依赖未就绪，需要先按项目文档初始化，并记录验证限制。

## 8. 风险与注意事项

- 不要把社区平台的 Web UI 当成 Host 插件。
- 不要让社区平台自定义与生态 manifest 冲突的插件模型。
- 不要引入新的 UI 技术选型；若现有社区平台已用不同前端结构，需要先审计再决策。
