# 任务016.03：命令与导航视图 Compound 迁移

## 1. 任务目标

把 `CommandPalette / NavigationSplitView` 迁移为正式 Compound API，收口命令搜索面板与导航分栏视图的组合结构。

## 2. 父任务

- `任务016-组件库复杂组件Compound迁移.md`
- 对应阶段任务：`05-开发任务方案/任务09-复杂组件Compound-API与样式契约.md`

## 3. 涉及项目

- `Chips-ComponentLibrary/packages/components`
- `Chips-ComponentLibrary/packages/theme-contracts`
- `Chips-Host/src/renderer/declarative-ui`
- `Chips-Host/tests/unit`
- `生态共用技术文档/组件库`

## 4. 开发内容

1. 为 `CommandPalette` 建立 `Root / Input / List / Item / Group` Compound API，并继续保证命令触发走 Host command registry 或注入 adapter。
2. 为 `NavigationSplitView` 建立 `Root / Sidebar / Content / Detail` Compound API；若当前正式组件以 `ChipsSplitView` 或相邻 Workbench 组件承载，需要先明确命名和 scope 边界，再实施。
3. 补齐 TypeScript 声明、组件测试、a11y 规则、component contract 和公共文档。
4. 补齐 Host L8 `StandardCompoundSlotSchemas` 中本批组件对应 slot schema 与诊断测试。

## 5. 验收标准

- `CommandPalette` 的输入、列表、分组和条目 slot 规则明确，命令动作仍不直连业务函数。
- `NavigationSplitView` 的导航栏、内容区和详情区结构可被主题和 L8 识别。
- contract 覆盖公开 parts，L8 能校验 slot 类型和重复规则。
- 如发现 NavigationSplitView 缺少正式组件或命名边界不清，必须先登记问题工单或在本子工单内正式收口，不做临时替代。
