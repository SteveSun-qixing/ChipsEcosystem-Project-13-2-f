# 任务028：生态设置面板应用迁移

## 1. 任务目标

将 `Chips-EcoSettingsPanel` 迁移到新前端框架基线，使它成为主题治理、多语言治理、插件治理、组件矩阵、主题矩阵、预览与诊断的正式入口。

## 2. 对应阶段任务

- `05-开发任务方案/任务17-生态设置面板治理入口扩展.md`
- `05-开发任务方案/任务20-现有应用插件全量迁移.md`

## 3. 涉及项目

- `Chips-EcoSettingsPanel`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `ThemePack/*`
- `生态共用技术文档/协议与接口标准/07-运行时设置治理接口标准.md`

## 4. 开发内容

1. 重新核对 `manifest.yaml`、运行时权限、治理接口、现有页面和 `npm run verify` 链路。
2. 改造应用入口为 App/Scene/surface/commands 结构。
3. 将主题、多语言、插件、快捷方式、组件展示全部改为 SDK/Bridge 正式接口消费。
4. 使用 View/Stack/Grid/Form/List 统一声明式布局组织设置页，不保留手写页面壳层样式。
5. 增加组件矩阵、主题矩阵、组件 contract 状态、主题 contract 状态和缺失 token 诊断入口。
6. 增加预览与性能工具入口：组件预览、应用插件预览、卡片预览、箱子布局预览。
7. 接入统一导航、菜单、工具栏、焦点、键盘快捷键、a11y 和错误诊断。
8. 补充治理接口 mock、Host 集成 smoke、主题切换、语言切换和权限不足测试。

## 5. 验收标准

- 设置面板不直连 Host 内部模块或系统 API。
- 所有文案走 i18n，视觉走组件库和主题 token。
- 主题、语言和插件状态以 Host 返回为准，前端不手改治理状态。
- 该应用可以作为新框架治理能力的第一验收应用。

## 6. 验证命令

```bash
cd Chips-EcoSettingsPanel
npm run verify
```

## 7. 注意事项

- 应用插件快捷方式创建和删除必须由 Host 正式接口完成。
- 开发态与用户态工作区不能在前端混用。
- 本任务开发前必须重新核对 SwiftUI Settings/commands 场景、运行时设置治理接口和当前设置面板真实代码。
