# 任务029：卡片查看器应用迁移

## 1. 任务目标

将 `Chips-CardViewer` 迁移到新前端框架基线，使它成为 `.card` 与 `.box` 的正式查看入口，同时保持 Host 统一卡片显示链路的消费方定位。

## 2. 对应阶段任务

- `05-开发任务方案/任务20-现有应用插件全量迁移.md`
- `05-开发任务方案/任务29-成品测试空间与真实素材回归.md`

## 3. 涉及项目

- `Chips-CardViewer`
- `Chips-Host`
- `Chips-SDK`
- `Chips-ComponentLibrary`
- `Chips-BaseCardPlugin/*`
- `Chips-BoxLayoutPlugin/*`

## 4. 开发内容

1. 重新核对 `manifest.yaml` 中 `.card/.box` file-handler、权限、surface 和启动上下文。
2. 改造应用入口为 App/Scene/Document surface 模型，区分卡片文档、箱子文档和空启动场景。
3. 卡片显示只调用 SDK/Host 正式封面、复合卡片、打开与渲染接口。
4. 箱子显示只调用 Host box runtime 和已安装布局插件，不在查看器内重写布局逻辑。
5. 使用新组件库重构工具栏、路径栏、错误态、加载态、空态、最近打开、导出入口和诊断面板。
6. 接入主题、语言、窗口背景、菜单、快捷键、焦点、滚动所有权和 a11y。
7. 增加真实 `.card/.box` 文件回归，覆盖基础卡片组合、嵌套箱子、缺失插件、主题切换和语言切换。
8. 增加复合卡片 iframe 事件协议、文档高度、错误诊断和 cleanup 测试。

## 5. 验收标准

- 迁移后现有用户可见功能、交互路径、使用逻辑、状态流转和数据语义保持不变；本任务只切换到新框架架构与正式生态链路，不做产品行为重设计。
- 查看器不重写基础卡片分发、模板编译、iframe 拼接或箱子布局运行时。
- `.card` 与 `.box` 文件从 Host 启动上下文进入查看器后行为一致。
- 查看器与编辑引擎查看态共享同一显示契约。
- 主题和语言变化能同步到应用壳层与内容 iframe。

## 6. 验证命令

```bash
cd Chips-CardViewer
npm run lint
npm test
npm run build
npm run validate
```

## 7. 注意事项

- 查看器是应用套壳，不是渲染运行时本体。
- 不允许应用内私建第二套文件入口协议。
- 本任务开发前必须重新核对 SwiftUI Document/Window 场景、卡片显示标准和当前查看器代码。
