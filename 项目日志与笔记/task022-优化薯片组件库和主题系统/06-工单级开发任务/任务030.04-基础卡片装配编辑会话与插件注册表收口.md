# 任务030.04：基础卡片装配、编辑会话与插件注册表收口

## 1. 任务目标

收口编辑引擎作为官方编辑态本地运行时特例的核心链路：基础卡片描述符注册表、单卡 iframe 装配、复合卡片汇总、EditorHost、EditorSessionStore、资源桥与插件安装/启停刷新。

## 2. 背景

公共标准明确官方编辑引擎编辑态采用“双运行时、单数据源”：显示链路由 `BasecardDescriptor -> BasecardFrameHost -> 单卡 iframe -> CompositeCardAssembler -> CardWindow` 组成，编辑链路由 `BasecardDescriptor.renderEditor -> EditorSessionStore -> EditorHost -> EditPanel` 组成。该例外不得扩散给查看器或普通应用。

## 3. 开发内容

1. 复核 `src/basecard-runtime/`、`src/editor-runtime/`、`src/components/CardWindow/`、`src/components/EditPanel/` 当前实现与公共标准差距。
2. 确保基础卡片注册表通过内置描述符和 Host 已安装启用插件 `basecardDefinition` 建立，不扫描工作区源码，不按具体 cardType 写主流程硬编码。
3. 保持 `base.richtext`、`base.image`、`base.webpage` 等内置描述符只是注册表成员，不成为业务分支。
4. 收口 `BasecardFrameHost` 的主题注入、透明背景、`previewPointerEvents`、高度测量、node 选中、错误隔离与 cleanup。
5. 收口 `CompositeCardAssembler` 的顺序装配、内容驱动高度、选中状态和交互代理。
6. 收口 `EditorHost` 与 `EditorSessionStore`：稳定回调、防抖提交、资源导入/删除/释放、可见性/卸载 flush、错误隔离。
7. 补充基础卡片注册、iframe host、复合装配、编辑会话、PluginHost 与资源桥专项测试。

## 4. 验收标准

- 编辑引擎不得恢复整张 `client.card.compositeWindow.render(...)` 作为编辑态主入口。
- 编辑面板不得恢复 SDK iframe editorPanel 作为官方编辑引擎主编辑链路。
- 主流程无单一 cardType 硬编码分支，所有类型由 descriptor/alias 解析。
- 资源型基础卡片通过正式资源桥，运行时 URL 不污染持久化 YAML。
- 单卡 iframe 错误、loading、ready 和 cleanup 不影响整张卡片稳定性。
