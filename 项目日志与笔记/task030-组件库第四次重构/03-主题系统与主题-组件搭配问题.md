## 四、主题-组件交叉一致性问题（核心）

### 4.1 loading 状态三方死链（最高优先）

- 契约：`theme-interface.contract.json` 中 states 含 `"loading"` 共 **63 次**；
- 主题 CSS：`[data-state="loading"]` 选择器 **0 处**；
- 组件代码：`resolveInteractiveState`（index.js:2449-2475）**先判 disabled（2450）再判 loading（2454）**；所有交互组件 `disabledByState = disabled || loading` 后传入 → loading=true 时输出 `data-state="disabled"` + `aria-disabled="true"`，**loading 分支是死代码**；
- 影响：加载中的按钮被套 disabled 视觉（opacity: 0.6 + cursor: not-allowed），契约/主题/代码三方不一致。布局组件（layout-primitives normalizeState:121-135）因 disabled/loading 分开传入反而正常。

### 4.2 布局组件焦点样式死区

- 主题 CSS 为 9 个布局 scope 定义 `[data-state="focus"]`（layout-containers.css:31/50/137/142/171/222/274/356/402）；
- 但 `normalizeState`（layout-primitives.js:121-135）只产出 disabled/loading/error/active/idle，**无 focus/hover**；`createLayoutFocusHandlers`（174-193）只在回调里 onStateChange("focus")，**不更新 DOM 上的 data-state**；
- 结果：9 条焦点描边规则全部失效，布局组件无焦点反馈（image/progress/error-state 有 :focus-visible 兜底，布局组件无）。

### 4.3 menu/tooltip/popover 根节点与触发器无样式

- 代码输出：popover root/status（index.js:9665/9681）、menu root/trigger/status（10422/10492/10433）、tooltip root/trigger/status；
- 主题 CSS：只覆盖 content/arrow（overlays.css:73-127）与 menu content/item/group/separator（layout-containers.css:447-507）；
- 结果：这三个弹层的根节点/触发器无 surface、无定位基础样式。

### 4.4 约 28 个 scope 的 status part 无样式

代码输出但主题 CSS 无对应选择器的 part（摘录）：box:status、card-shell:status、checkbox:status、command-palette:status、data-grid:status、date-time:status、empty-state:status、input:status、inspector:section/status、notification:status、panel-header:status、radio:item/status、scroll-view:content/status、section:status、select:status、split-pane:status、split-view:status、stack:item/status、switch:status、tabs:status、toast:list/status、tree:label、view:status、virtual-list:viewport/content/status、card-cover-frame:frame-container/iframe、composite-card-window:root/iframe、divider:label、media:control、loading-boundary:skeleton、tool-window:control。

- 特别严重：**错误状态节点（role=status）在 20+ 组件上输出但完全无样式，错误信息不可见**；
- media "control" vs "controls" 单复数分裂：契约同时声明 control+controls，代码只输出 controls（index.js:4505），CSS 两套选择器都在（display.css:303/311/321-322），`[data-part="control"]` 永不命中；
- loading-boundary "skeleton" part 空挂：CSS 样式化（feedback.css:431/435）但契约与代码只有 root/content/fallback/status；
- tool-window CSS 期待 `[data-part="controls"] [data-part="control"]` 后代（layout-containers.css:918/923），代码无 control。

### 4.5 token 定义后无消费方（D2=60、D4=48）

- 16 个组件（combo-box/date-picker/number-input/rating/search-field/secure-field/segmented-control/slider/stepper/text-field/text-area/time-picker）的 `focus-outline` token 已定义、契约已要求，但主题 CSS 从不消费 → **这些组件无焦点描边**；
- 各 root-surface-disabled、badge-icon-color-*、form-field-*/form-group-* 整棵子树、loading-boundary-skeleton-motion-*、progress-range-motion-* 等定义后无消费方。

### 4.6 Primitive 与 Chips* 布局组件双实现串扰

- `@chips/primitives` 与 `components/layout-primitives.js` 各有一套布局组件，输出**完全相同**的 data-scope/data-part="root"：
  - box（primitives 197-201 vs layout-primitives 482）、stack（209-213 vs 548）、inline（203-207 vs 600）、grid（215-219 vs 659）、text（221-225 vs index.js 1068）、label（227-231 vs 1118）；
- 但能力不对称，同一选择器命中效果不同：

| 主题选择器 | 依赖属性 | Chips* | 原始 Primitive |
|---|---|---|---|
| `[data-direction="horizontal"]`（layout-containers.css:68） | data-direction | ✅ 输出 | ❌ 不输出 |
| `[data-align/justify/wrap]`（77-133） | 同左 | ✅ | ❌（props 落入 rest 变无效 DOM 属性） |
| `[data-columns="auto"]`（164） | data-columns | ✅ | ❌ |
| `[data-part="item"]`（159） | item 包裹层 | ✅ | ❌ 直接渲染 children |
| var(--chips-box-padding/radius)（39-40） | 内联 CSS 变量 | ✅ | ❌ |
| `[data-state="active"]`（46 等） | active prop | ✅ | ❌ 恒 idle |

- 结果：用 Primitive 时 direction/gap/align/justify/wrap/columns/padding/radius/active 全部静默失效，且无 status 节点、无 item 包裹层。

### 4.7 CardViewer 越契约输出状态

- composite-card-window 契约 states：idle/resolving/rendering/ready/degraded/error/disabled（无 loading）；
- `Chips-CardViewer/src/components/HostedDocumentWindow.tsx:570/582` 直接输出 `data-state="loading"/"error"`，绕过 card-runtime 的 `resolveCompositeCardWindowState`（states.js）。
