# 分报告 04：多语言（i18n）系统问题

> 调查日期：2026-08-06
> 调查对象：`生态共用技术文档/协议与接口标准/03-多语言规范.md`、`Chips-Host`（register-host-services.ts 等）、`Chips-ComponentLibrary`、`Chips-SDK`、9 个应用插件
> 关键结论：生态多语言的"契约骨架"（4 动作 + 权限 + language.changed 事件 + SDK 类型 + 组件 i18n props + 同步 adapter）已经打通；但**词典加载链、缺失 key 治理门禁、语言检测/持久化、RTL、复数性别、格式化等规范承诺的核心运行时能力均未实现**——"协议已冻结、运行时未收口"。

---

## 一、契约骨架（合规项）

1. Host 4 个动作全部实现且带权限描述符：`i18n.getCurrent`(i18n.read)、`i18n.setCurrent`(i18n.write)、`i18n.translate`(i18n.read)、`i18n.listLocales`(i18n.read)（register-host-services.ts:4420-4483）；
2. i18n.write 权限检查真实生效（kernel 路由层 guardPermissions，router.ts:155-180，无权限抛 PERMISSION_DENIED）；
3. `language.changed` 事件链路完整：setCurrent → kernel.events.emit（:4445）→ IPC 广播（chips-ipc.ts:128-148）→ preload eventAdapter（create-bridge.ts:184-194）→ RuntimeClient.on（runtime-client.ts:90-106）；SDK `i18n.onChanged` 挂同一事件（i18n.ts:42-44）；
4. 同步 adapter 完备：`createChipsI18nText`（hooks/src/index.js:298-320）、`useChipsI18nText`（:1526-1533）、`useChipsI18n`（:1506-1524，setLocale 走 Host）；查找顺序 [locale, ...fallbackLocales, fallbackLocale, defaultLocale] → key 本身，与规范一致；
5. 应用侧语言包 zh/en 两侧 key 数量一致（无缺译），语言切换链路可用。

## 四、修复优先级建议

1. **P0**：Host 词典加载链（插件/应用/生态三级）+ translate 语义对齐规范（回退而非抛错）+ 语言持久化 + 缺失 key 治理门禁；
2. **P0**：组件库硬编码文案全部收口到默认 i18n key，生态词典补齐 systemUx.*/component.* 默认文案；
3. **P1**：组件默认 key 进入应用/生态语言包；同步 adapter 统一（清理 7 份私有 formatMessage）；
4. **P1**：EditingEngine 解除与 Host i18n 的解耦；PhotoViewer RTL 桩修复；
5. **P2**：ICU plural/select、语言家族回退、统一日期数字格式化 API。
