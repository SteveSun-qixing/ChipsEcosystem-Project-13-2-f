# 分报告 05：宿主链路与应用消费问题

> 调查日期：2026-08-06
> 调查对象：`Chips-EcoSettingsPanel`、`Chips-MusicPlayer`、`Chips-PhotoViewer`、`Chips-VideoPlayer`、`Chips-BookReader`、`Chips-RichTextEditor`、`Chips-CardViewer`、`Chips-EditingEngine`、`Chips-CommunityClient`、`Chips-Scaffold`
> 关键结论：**9 个应用里 8 个没有真正消费组件库**。"组件不可用"的第一证据来自宿主链路缺口（工单120/130：Web 宿主不注入主题 CSS/字体 → 图标显示英文文本）；应用侧普遍绕过组件库自造私有 UI（189 个私有 token、7 份重复 formatMessage、1 套第二主题系统、1 套显式解耦 i18n）。

## 六、脚手架模板质量（唯一干净参照系）

- Chips-Scaffold app-standard 模板结构完整：AppProviders/AppRoot/AppRuntimeProvider/AppShell/scene-registry + commands/i18n/runtime/theme/scenes/views/testing/preview；
- 模板 AppShell 第一屏：header（ChipsText + ChipsBadge + ChipsButton 语言切换）→ 命令行（ChipsMenuBar + ChipsToolbar）→ ChipsNavigationSplitView（Sidebar/Content/Detail 内嵌 ChipsCommandPalette），全部被 ChipsErrorBoundary/LoadingBoundary/ScrollView/Stack/View 包住；
- 模板 app-shell.css：硬编码 0、私有 token 0，只用 `var(--chips-sys-color-*, var(--chips-base-color-*))` 双回退；
- i18n 用 useChipsI18n + useChipsI18nText + resolveI18nText；
- **结论：模板即"标准答案"，问题在生成后的应用没有按模板演进**（媒体三件套 AppShell 26 行私有 Stage 直出 vs 模板 228 行组件库壳层）。

## 七、宿主链路缺口（组件"看起来坏了"的直接证据）

1. **工单120（已处理）**：社区 Web 宿主不注入主题 CSS/图标字体 → ChipsIcon 按钮显示 play_arrow/skip_next 英文文本；
2. **工单130（待处理）**：布局插件 iframe 文档（box-service 生成 view/editor）只注入 token 不注入主题 @font-face → Material Symbols 缺失，grid_view/expand_more 显示为文本；**卡片窗口链路同病**；
3. 工单112（已处理）：cpx 未转换导致整个应用排版乱套（见分报告 03 的转换链路确认——当前 4 入口已覆盖）。
